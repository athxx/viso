$ viso explain E3101
E3101 Unknown Property
error, compiler, view

A node binds a property that its type's schema does not declare. Widgets expose a fixed schema, user components expose their `input`s, parent-provided properties such as `grid.row` come from the parent container, and a template's `use` takes the template's parameters; any other name is rejected. The usual cause is a misspelling, and the diagnostic suggests the nearest known name. In a `style`, a property that is not styleable is reported the same way.

Example:
    component A {
        view {
            Text { text: "a"; opacty: 0.5; }
        }
    }

Fix:
  Use a property the schema declares (often the suggested spelling); query the schema to see every property of the type.

    Text { text: "a"; opacity: 0.5; }

Suggested actions:
  viso schema <Component>
  viso schema <Component> --json

$ viso explain E2302
E2302 Unreachable Pattern
warning, compiler, type

Match arms are tried in order, so an arm whose pattern is fully covered by the arms before it can never run. This usually means a catch-all `_` or binding arm was placed too early, or a case was written twice.

Example:
    enum Shape { Dot; Circle(I64); }

    fn size(s: Shape) -> I64 {
        match s {
            _ => 0,
            Shape::Dot => 1,
        }
    }

    component A {
        view { Text { text: "a"; } }
    }

Fix:
  Remove the unreachable arm, or move the more specific arms before the catch-all.

    match s {
        Shape::Dot => 1,
        _ => 0,
    }

$ viso explain E5101
E5101 State Reset on Hot Reload
warning, compiler, hot_reload

When a reload changes a state's type, the live value is carried into the new type when the new type can hold it, or through a `@migrate` function from the old type. If neither works, because the value does not fit or the migrate function faults, the state restarts from its new initializer and the reload reports this warning. The rest of the reload still commits.

Example:
    Before the edit, the running view holds `count == 300`:

        state count = 0;

    After the edit the state is an `I8`, which cannot hold 300, and there is
    no `@migrate` function, so `count` resets to 1 with E5101:

        state count: I8 = 1;

Fix:
  If the value matters, add a `@migrate` function from the old type that always produces a valid new value; otherwise the reset is expected and the warning can be ignored.

    @migrate(from: "I64")
    fn clamp(old: I64) -> I8 { if old > 127 { 127 } else { 0 } }

Suggested actions:
  viso run

$ viso explain C0004
C0004 unknown configuration key
config

The manifest names a table or key the configuration schema does not define, often a misspelling. It is an error: a setting that never takes effect would build something other than what its author asked for.

Fix:
  Remove the key, or correct its spelling to the key the diagnostic suggests.

Suggested actions:
  viso config validate

$ viso explain ENV_LOCK_HELD
ENV_LOCK_HELD Another viso process holds a lock the command needs free.
cli

Builds, dev sessions and cleaning take locks under `target/viso/locks` so two processes never write the same output; another live process holds the one this command needs. A lock its holder stopped refreshing is taken over.

Fix:
  Wait for the other command to finish, or stop it; the diagnostic names its process and age.
