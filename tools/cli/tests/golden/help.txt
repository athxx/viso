$ viso --help
Build, check and run Viso applications

Usage: viso [OPTIONS] <COMMAND>

Examples:
  viso new my_app    # create an app in `my_app/`
  viso run           # build and run the app here, hot reloading it
  viso check --json  # check the sources, as JSON events

PROJECT
  new         Create a Viso project from a template: an app, a game, a web app or a library
  doctor      Examine this machine for developing Viso apps: toolchains, the project, a target's SDK
  config      Show where each configuration value comes from, or validate it

MOBILE DEV ENVIRONMENT
  android     Manage the Android SDK and the emulator profiles `viso run android` runs on
  ios         Manage the iOS Simulator runtimes and the profiles `viso run ios` runs on

DEVELOP
  run         Build a dev artifact and run it, hot reloading edits as they are saved
  build       Build the app for a target and write it to `dist/`, without running it
  serve       Build a dev artifact for a browser and serve it, hot reloading it

LANGUAGE
  fmt         Lay out `.vs` sources in the one canonical format
  check       Check the project's `.vs` sources and `Viso.toml` without building
  schema      Show the typed schema of a widget, component, native library, function or type
  explain     Explain a diagnostic code: why it is raised and how to fix it
  dump        Print one of the compiler's IRs of the project: syntax tree, HIR, view, behavior, shader, systems
  lsp         Start the `.vs` language server for an editor, speaking LSP over stdio

TEST / DEBUG
  test        Run the project's tests: unit, UI, game
  snapshot    Take the snapshots UI scenarios take, and hold them to their goldens
  inspect     Inspect the running app: its nodes and their source, what it holds for them, what it drew
  profile     Sample the frames the running app draws: their time, phase by phase, and the work they count
  game        Read a state of, or record input from, the game `viso run` is playing

DELIVERY
  package     Build the app as its platform ships it, signed: an `.app` and `.dmg`, an `.ipa`, an APK and app bundle, an archive
  export      Generate source a web project owns from the app's view: plain HTML and CSS

MAINTENANCE
  clean       Remove `target/viso/`: builds, caches and dev state, never `dist/`
  completion  Write the script that completes `viso` commands in a shell

Options:
      --project <PATH>     Use the project at PATH, a directory or its `Viso.toml`, not the one found upward
      --json               Write JSON events to stdout, one per line, instead of text
  -q, --quiet              Print only errors, requested paths and the summary
  -v, --verbose            Also print the resolved configuration, the tools run and stage times
      --color <WHEN>       When to color human output; `auto` is a terminal without `NO_COLOR` [default: auto] [possible values: auto, always, never]
      --offline            Use no network: Cargo and downloads work from what is on disk
      --locked             Require `Cargo.lock` to be up to date
      --jobs <N>           Run at most N jobs at once
      --profile <NAME>     The build profile [possible values: dev, release, shipping]
      --target-dir <PATH>  Put build output under PATH instead of `target/`
  -h, --help               Print help
  -V, --version            Print version

Notes:
  Run `viso <command> --help` for a command's arguments and options.

$ viso new --help
Create a Viso project from a template: an app, a game, a web app or a library

Usage: viso new [OPTIONS] <PATH>

Examples:
  viso new my_app                               # an app in `my_app/`, a Git repository
  viso new . --template game                    # a game in the current directory, named after it
  viso new widgets --template library --no-git  # components for other apps, without Git

Arguments:
  <PATH>  The directory to create the project in, made with its parents when missing; `.` for the current one

Options:
      --template <NAME>   What the project starts as [default: app] [possible values: app, game, web, library]
      --name <NAME>       The package name; the directory's name when omitted
      --edition <YEAR>    The Rust edition the package is written in [default: 2024] [possible values: 2021, 2024]
      --no-git            Do not make the directory a Git repository
      --force-empty-dir   Create the project in a directory that has files already; none of them is replaced, and one the project would write is an error
      --framework <PATH>  Depend on the framework at this path (a checkout, or its `crates/viso`) rather than on the release of this CLI's version
  -h, --help              Print help

Global options:
      --project <PATH>     Use the project at PATH, a directory or its `Viso.toml`, not the one found upward
      --json               Write JSON events to stdout, one per line, instead of text
  -q, --quiet              Print only errors, requested paths and the summary
  -v, --verbose            Also print the resolved configuration, the tools run and stage times
      --color <WHEN>       When to color human output; `auto` is a terminal without `NO_COLOR` [default: auto] [possible values: auto, always, never]
      --offline            Use no network: Cargo and downloads work from what is on disk
      --locked             Require `Cargo.lock` to be up to date
      --jobs <N>           Run at most N jobs at once
      --profile <NAME>     The build profile [possible values: dev, release, shipping]
      --target-dir <PATH>  Put build output under PATH instead of `target/`

Notes:
  The templates are built in, so it needs no network. A directory with files is
  refused unless `--force-empty-dir`, which still replaces none of them.
  `--framework <path>` depends on a checkout of the framework instead of a release.

$ viso doctor --help

      --offline            Use no network: Cargo and downloads work from what is on disk
      --locked             Require `Cargo.lock` to be up to date
      --jobs <N>           Run at most N jobs at once
      --profile <NAME>     The build profile [possible values: dev, release, shipping]

Usage: viso ios [OPTIONS] <COMMAND>

Examples:
  viso ios list                     # the Simulator runtimes and the default
  viso ios simulator create iphone  # create a phone profile

Commands:
  list       List the Simulator runtimes installed and the one Xcode can install, and which is the default
  use        Make a Simulator runtime the default, having Xcode install it first when it is not
  doctor     Check Xcode, its license, the Simulator runtime and the profiles
  simulator  The simulator profiles

Options:
  -h, --help  Print help

Global options:
      --project <PATH>     Use the project at PATH, a directory or its `Viso.toml`, not the one found upward
      --json               Write JSON events to stdout, one per line, instead of text
  -q, --quiet              Print only errors, requested paths and the summary
  -v, --verbose            Also print the resolved configuration, the tools run and stage times
      --color <WHEN>       When to color human output; `auto` is a terminal without `NO_COLOR` [default: auto] [possible values: auto, always, never]
      --offline            Use no network: Cargo and downloads work from what is on disk
      --locked             Require `Cargo.lock` to be up to date
      --jobs <N>           Run at most N jobs at once
      --profile <NAME>     The build profile [possible values: dev, release, shipping]
      --target-dir <PATH>  Put build output under PATH instead of `target/`

Notes:
  Profiles are kept in `~/.viso/` (`$VISO_HOME`); `viso run ios --device <id>`
  runs on one. Every `viso ios` command needs macOS and Xcode.

$ viso ios use --help
Make a Simulator runtime the default, having Xcode install it first when it is not

Usage: viso ios use [OPTIONS] <RUNTIME>

      --jobs <N>           Run at most N jobs at once

$ viso run --help
Build a dev artifact and run it, hot reloading edits as they are saved

Usage: viso run [OPTIONS] [TARGET] [-- <APP_ARGS>...]

Examples:
  viso run                         # on this machine
  viso run ios --device iphone     # on the simulator profile `iphone`
  viso run web-gpu --browser none  # serve it, opening no browser

Arguments:
  [TARGET]       Where to run: this machine when omitted [possible values: ios, android, web-gpu, web-dom, web-hybrid]
  [APP_ARGS]...  Arguments for the app, after `--`

Options:
      --device <ID>      The simulator or emulator profile (`ios` and `android` only)
      --browser <NAME>   The browser to open (`web-*` only): `chrome`, `safari`, `firefox`, or `none` to only serve
      --no-hot-reload    Keep the dev session up but apply no edit to the app: each is compiled and reported, not sent
      --profile-frame    Draw the frame time over the app's windows, and report every frame it draws: a `profile` event each under `--json`, a line a second otherwise
      --inspect          Follow what happens in the app's first window, as `viso inspect` does: an `inspect` event each under `--json`, a line each otherwise
      --open             Open the page in a browser (`web-*` only), under `--json` too
      --env <KEY=VALUE>  A variable the app is launched with; repeatable. A value whose name looks secret is never printed
      --cwd <PATH>       The app's working directory (this machine only): the project root when omitted
  -h, --help             Print help

Global options:
      --project <PATH>     Use the project at PATH, a directory or its `Viso.toml`, not the one found upward
      --json               Write JSON events to stdout, one per line, instead of text
  -q, --quiet              Print only errors, requested paths and the summary
  -v, --verbose            Also print the resolved configuration, the tools run and stage times
      --color <WHEN>       When to color human output; `auto` is a terminal without `NO_COLOR` [default: auto] [possible values: auto, always, never]
      --offline            Use no network: Cargo and downloads work from what is on disk
      --locked             Require `Cargo.lock` to be up to date
      --jobs <N>           Run at most N jobs at once
      --profile <NAME>     The build profile [possible values: dev, release, shipping]
      --target-dir <PATH>  Put build output under PATH instead of `target/`

Notes:
  `ios` and `android` run on a simulator or emulator profile: see
  `viso ios simulator list` and `viso android emulator list`. The web targets
  build for a browser and serve it as `viso serve` does. The app's own arguments
  follow `--`. `--profile-frame` draws the frame time over the app's windows and
  reports its frames as `viso profile` measures them.
