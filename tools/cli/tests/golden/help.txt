$ viso --help
Build, check and run Viso applications

Usage: viso [OPTIONS] <COMMAND>

Examples:
  viso run           # build and run the app here, hot reloading it
  viso run ios       # the same on an iOS Simulator
  viso check --json  # check the sources, as JSON events

PROJECT
  config      Show where each configuration value comes from, or validate it

MOBILE DEV ENVIRONMENT
  android     Manage the Android Emulator profiles `viso run android` runs on
  ios         Manage the iOS Simulator profiles `viso run ios` runs on

DEVELOP
  run         Build a dev artifact and run it, hot reloading edits as they are saved
  build       Build the app for a target and write it to `dist/`, without running it
  serve       Build a dev artifact for a browser and serve it, hot reloading it

LANGUAGE
  fmt         Lay out `.vs` sources in the one canonical format
  check       Check the project's `.vs` sources and `Viso.toml` without building
  schema      Show the typed schema of a widget, native library, function or type

TEST / DEBUG
  test        Run the project's tests: unit, UI, game
  game        Read a state of, or record input from, the game `viso run` is playing

MAINTENANCE
  clean       Remove `target/viso/`: builds, caches and dev state, never `dist/`
  completion  Write the script that completes `viso` commands in a shell

Options:
      --project <PATH>     Use the project at PATH, a directory or its `Viso.toml`, not the one found upward
      --json               Write JSON events to stdout, one per line, instead of text
  -q, --quiet              Print only errors, requested paths and the summary
  -v, --verbose            Also print the resolved configuration, the tools run and stage times
      --color <WHEN>       When to color human output; `auto` is a terminal without `NO_COLOR` [default: auto] [possible values: auto, always, never]
      --offline            Use no network: Cargo and downloads work from what is on disk
      --locked             Require `Cargo.lock` to be up to date
      --jobs <N>           Run at most N jobs at once
      --profile <NAME>     The build profile [possible values: dev, release, shipping]
      --target-dir <PATH>  Put build output under PATH instead of `target/`
  -h, --help               Print help
  -V, --version            Print version

Notes:
  Run `viso <command> --help` for a command's arguments and options.

$ viso config --help
Show where each configuration value comes from, or validate it

Usage: viso config [OPTIONS] <COMMAND>

Examples:
  viso config show                           # every key, its value and its origin
  viso config get profile.release.opt_level  # one key
  viso config validate                       # every problem of the configuration

Commands:
  show      Every configuration key, its value and the layer it came from
  get       One configuration key, its value and the layer it came from
  path      The path of the `Viso.toml` in use
  validate  Check `Viso.toml` and the `VISO_*` environment, reporting every problem

Options:
  -h, --help  Print help

Global options:
      --project <PATH>     Use the project at PATH, a directory or its `Viso.toml`, not the one found upward
      --json               Write JSON events to stdout, one per line, instead of text
  -q, --quiet              Print only errors, requested paths and the summary
  -v, --verbose            Also print the resolved configuration, the tools run and stage times
      --color <WHEN>       When to color human output; `auto` is a terminal without `NO_COLOR` [default: auto] [possible values: auto, always, never]
      --offline            Use no network: Cargo and downloads work from what is on disk
      --locked             Require `Cargo.lock` to be up to date
      --jobs <N>           Run at most N jobs at once
      --profile <NAME>     The build profile [possible values: dev, release, shipping]
      --target-dir <PATH>  Put build output under PATH instead of `target/`

Notes:
  `Viso.toml` is the source of truth: `viso config` reads it and never writes it.
  A value comes from the first of: a flag, a `VISO_*` variable, the profile's
  table, the manifest, the default.

$ viso run --help
Build a dev artifact and run it, hot reloading edits as they are saved

Usage: viso run [OPTIONS] [TARGET] [-- <APP_ARGS>...]

Examples:
  viso run                         # on this machine
  viso run ios --device iphone     # on the simulator profile `iphone`
  viso run web-gpu --browser none  # serve it, opening no browser

Arguments:
  [TARGET]       Where to run: this machine when omitted [possible values: ios, android, web-gpu, web-dom, web-hybrid]
  [APP_ARGS]...  Arguments for the app, after `--`

Options:
      --device <ID>      The simulator or emulator profile (`ios` and `android` only)
      --browser <NAME>   The browser to open (`web-*` only): `chrome`, `safari`, `firefox`, or `none` to only serve
      --no-hot-reload    Keep the dev session up but apply no edit to the app: each is compiled and reported, not sent
      --open             Open the page in a browser (`web-*` only), under `--json` too
      --env <KEY=VALUE>  A variable the app is launched with; repeatable. A value whose name looks secret is never printed
      --cwd <PATH>       The app's working directory (this machine only): the project root when omitted
  -h, --help             Print help

Global options:
      --project <PATH>     Use the project at PATH, a directory or its `Viso.toml`, not the one found upward
      --json               Write JSON events to stdout, one per line, instead of text
  -q, --quiet              Print only errors, requested paths and the summary
  -v, --verbose            Also print the resolved configuration, the tools run and stage times
      --color <WHEN>       When to color human output; `auto` is a terminal without `NO_COLOR` [default: auto] [possible values: auto, always, never]
